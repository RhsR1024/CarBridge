# CarBridge 0.1.2 / MediaBridge 2.3.2

日期：2026-10-02。配套版本：CarBridge 0.1.2 / 102；MediaBridge 2.3.2-carbridge-26100203 / 26100203，含正式和手机 Debug。沿用已有测试签名及外部 CarPlay 认证输入。

## 设备反馈与变更

用户确认：0.1.1 的通用 Android + 明确直连 + 主动播放已出声。新日志 `mediabridge-probe-20261002-084126-350.log.txt` 显示新版手机调试后端已连接，但 08:18 和 08:25 的进程启动后未出现通知监听连接成功，导出时为“已授权，正在恢复监听；下次重试 60 秒”。历史 07:27 的成功绑定属于上一版本进程，不能作为当前监听就绪证据。

直连时 MediaBridge 按协作规则排除 CarBridge，故它的小窗不显示此来源。这和此前 AUTO 因通知监听未连接而等待是两个独立原因。恢复手机桥接需要重新开关新版 Debug 的通知使用权，确认输入已连接，再使用 AUTO / BRIDGE。

用户随后验证：重新开关新版 Debug 的通知使用权并切回 AUTO 后，声音和歌曲显示同时恢复。该结果验证当前设备的恢复路径，不代表应用会自动恢复所有 ROM 的通知绑定。

本次修改：

- 首页及 CarPlay Activity 的系统初始方向由固定横屏改为继承前页，在创建窗口前及接收返回 Intent 时应用保存的方向；新安装默认仍为固定横屏。用于消除固定竖屏返回首页时额外的横屏切换。
- 通用 Android / BYD 的 DIRECT 选项改名为“本机直连（不经 MediaBridge）”；吉利仍为 ECARX 直连，路由和音频策略未变。
- MediaBridge 向 CarBridge 补充具体等待原因，分别提示通知使用权、通知监听未连接、媒体后端未就绪或桥接停用；仅诊断原因变化不递增所有权版本。
- CarBridge 记录实际配套包及策略条件，重复等待提示去重，保留有效播放事件。移除重复的 `.dev` 包可见性声明；不将其当作无声原因。
- 设置明确说明直连不显示 MediaBridge 卡片，以及取得原生竖屏的现有配置步骤。
- 按用户确认增加“转屏时更新 CarPlay 原生布局”，默认关闭；只在自动方向、CarPlay 前台且获得窗口焦点时生效。横竖方向和窗口尺寸稳定 1.2 秒后重新连接，采用最新尺寸。短暂转回、返回首页或关闭开关会取消待执行请求；同一方向内的尺寸微调不重连。
- 根据 08:54 日志，CarBridge MediaSession 提供 `title=周铁男 - 三国杀`、空 artist/album、时长 199722ms，原先 `lookupAllowed=false` 是信息不完整而不是匹配错歌词。新增“缺失歌手时的标题格式”：默认保留原始信息，可选“歌手 - 歌曲名”或相反顺序。用户确认的示例选前者后输出歌名“三国杀”、歌手“周铁男”，桥接及直连使用同一份结果。已有歌手、多个分隔符、空片段、多行标题不拆分；不把所有横线标题当作缺失标签，也不改变底层 iAP2 字段或曲目代次。

标题格式选择沿用“应用并重新连接”流程，避免在同一连接内混用不同元数据解释下的资源。封面仍优先原生，原有歌词检索开关及匹配规则保留。歌曲名/歌手补齐允许启动歌词查找，不保证在线库收录此演唱者的版本；专辑仍未知，不从封面文字猜测。

## 原生旋转边界

默认关闭新增开关时，自动旋转仍保持当前连接画布。打开开关后通过显式允许的重连重新协商横竖画布，让 iPhone 重新布局；这会短暂中断画面和声音，音乐互斥下可能需要再次主动播放。固定竖屏也可以在首页断开后重新连接获得。不断连的原生动态显示协议尚未验证；没有发送猜测命令或绕过播放资格。重新协商后的实际布局、触摸与连续快速转屏收敛仍须设备验证。

## 验证与交付

构建及本机测试结果待本轮构建后补充。设备验收：固定横屏/固定竖屏/自动时首页与 CarPlay 往返、通知重新授权后桥接声音和歌曲、音乐互斥、后台播放及方控。没有 ADB 连接，不能以本机测试替代这些结果。
