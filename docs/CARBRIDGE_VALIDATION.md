# CarBridge 验证与验收方案

版本：0.1；日期：2026-10-01；实施更新：2026-10-02。本机自动化、构建和签名检查已完成，目标车机验收未执行。结果见 [本机验证报告](LOCAL_VALIDATION_2026-10-02.md)。覆盖 [规格](CARBRIDGE_SPEC.md) 全部需求；任务关联见 [实施计划](CARBRIDGE_IMPLEMENTATION_PLAN.md)。

## 1. 分清验证层次

| 层次 | 能证明什么 | 不能代替什么 |
| --- | --- | --- |
| 文档/静态检查 | 链接、任务覆盖、源码事实和设计一致性 | 车机注册、听音、iPhone 执行 |
| 单元与状态机测试 | 解析、顺序、门控决策、幂等和旧回调拒绝 | Android 真正失焦、ECARX 真实行为 |
| Android/两端合同测试 | MediaSession、IPC 身份与交接、URI 读权限 | 特定 ROM 的来源规则和方控事件 |
| 目标车机 + iPhone | 两种模式、真实歌曲卡片、声音互斥、按键效果和 OEM 图标 | 未测试 ROM/iOS/播放器的兼容性 |

本轮通过 535 项自动化测试与两包构建检查。下表包含实际设备标准，不能据本机结果整体勾选；逐项本机覆盖与设备 NOT RUN 见报告，现场补录 PASS / FAIL 并附证据。

## 2. 环境与样本

记录：车机型号、ROM 完整版本、Android API、ECARX 组件版本；CarBridge/MediaBridge APK 包名、versionCode、提交、签名摘要；连接方式；iPhone 型号/iOS；播放器名称/版本；网络状态、互斥开关和实际路由。

目标车已知参考：Android 11 / API 30、`999722 FX11-A2`、日志 ROM `antora1000_e245_car-userdebug 11 23.08.01.261710.262921 262921 test-keys`。该记录是先前日志环境，不应假定未来测试时完全相同。

至少包含：常规歌曲、同名不同作者、同曲不同版本/现场版、中文与英文、纯音乐、无专辑/封面、已缓存和未缓存曲目、较长音频。iPhone 上选择用户实际使用的播放器；车机端选择至少两款实际音乐应用并包含原生来源/收音机（若设备支持）。音量固定，测试时同时观察手机播放器和车机卡片。

两种模式分别测试前台 CarPlay、返回车机桌面、其他应用前台。有线/无线仅在设备与构建支持时分别覆盖；未具备硬件的路径标 NOT RUN，不能据此宣称通过。

## 3. 自动化与构建检查

遵循上游 [BUILD.md](BUILD.md) 和 [TESTING.md](TESTING.md)。Windows 使用仓库 Gradle wrapper：

```powershell
.\gradlew.bat :shared:testDebugUnitTest :common:testDebugUnitTest :mobile:lintDebug :mobile:assembleDebug
```

新增模块的单元/合同测试加入对应任务。只为有实际风险的逻辑写测试：增量协议、状态机、乱序消息、失焦后缓冲重启、资源串歌、权限和命令重复；不要用只检查私有方法调用次数的测试代替行为验证。

车机连接包另用 `:mobile:assembleStandaloneDebug`，前提是配置有效 `DIPLAY_AUTH_ASSETS_DIR`；普通 `assembleDebug` 无认证身份，不等于可连 iPhone。按发布变体另执行 lintRelease/assembleRelease；不得移除守卫为构建造假通过。

## 4. 功能验收矩阵

下列时限是首轮验收目标，不是当前性能实测值。以同一设备单调时钟和屏幕/音频观察标记测量；若平台导致调整，必须写明依据，不悄悄放宽。

| ID | 场景/操作 | 通过标准 | 必需证据 |
| --- | --- | --- | --- |
| V01 | 干净 checkout 配置依赖并构建；与 DiPlay 同装 | 构建通过；包名、authority、通知不冲突；独立启动 | 提交、环境、任务结果、APK 哈希与安装包信息 |
| V02 | 回放和实测 Now Playing 增量帧 | 字段/单位与手机一致；未知/截断帧不崩溃；两接收链一致 | 脱敏 fixture、字段表、手机与状态日志 |
| V03 | 同名切歌、仅部分字段更新、快速连切 | 不丢同曲字段、不沿用旧曲封面/歌词；新旧连接不混合 | Store 测试与切歌录屏 |
| V04 | 播放、暂停 10 秒、seek 前后、变速（若支持） | 暂停冻结，继续/seek 对齐；可用时间轴误差目标 ≤1 秒；未知位置明确标未知 | 手机进度与快照基准对比 |
| V05 | 新版 MB 桥接中播放歌曲 | 小窗与 MediaSession 歌名/歌手/专辑/状态一致；文字变化收到后目标 1 秒内更新 | 小窗、通知与手机画面 |
| V06 | 桥接前台/后台上下曲、明确播放/暂停 | 每次按键只执行一次，暂停不会变播放；真实状态回报可关联 | MB commandId → CB → HID → 手机变化 |
| V07 | 自动模式在 MB 忽略/取消忽略 CarBridge | 忽略后直连、解除后桥接；两端完成 ACK；20 次切换零双路发布/重复切歌 | route epoch、两端输出/命令事件序列 |
| V08 | 明确直连且未勾忽略；明确桥接且已忽略 | 前者协议有效排除且不暗改名单；后者显示冲突并等待；设置变更本身不抢播 | 设置、策略 revision、实际路线 |
| V09 | 旧 MB/未安装 MB/版本不兼容 | 旧版自动明确不可用；手动桥接/直连按配对说明有效；无 MB 可独立直连 | 版本与配置、状态画面、方控结果 |
| V10 | CarBridge 自身包名 ECARX 初始化/注册/选源 | 可注册、能接实际媒体回调；只连接和注册不暂停其他音乐 | SDK 组件/方法/返回值、音频观察 |
| V11 | 直连上下曲/PLAY/PAUSE/切换，前后台分别执行 | 四种明确指令语义正确，一次动作一次执行，连续操作稳定 | 回调、发送与手机状态；不能只留 sent=true |
| V12 | A=车机音乐，B=CarBridge；A播→B主动播→A主动播→B主动播循环 | 后主动者可听，先播放者暂停/让位；20 轮无持续双播/反抢；CB 收到失焦后本地静音目标 ≤300ms | 双端播放状态、声音录制/观察、意图与焦点日志 |
| V13 | 拒绝/延迟焦点、失焦后继续来 PCM、补缓冲重启 | 门保持关闭、旧缓冲不漏音；失败不会发布假 PLAYING；过期 gain 不恢复 | fake focus 测试、AudioTrack/门控记录、听音 |
| V14 | 另一应用播放中连接/重连手机，接收初始 PLAYING/换曲/封面 | 不自动抢播；新明确手机/界面播放才重新申请；无法区分的状态保持让位 | 初始状态、意图来源、requestPlay 记录 |
| V15 | 通话、Siri、导航提示；中断期间用户切本地音乐 | 提示/通话功能正常；结束只恢复未被替代的原意图，不覆盖新音乐；导航不切歌曲来源 | 各音频通道、恢复令牌、声音观察 |

| V18 | 断开、切换 iPhone、快速重连、页面反复前后台 | 清理旧 session/资源/焦点；暂停可恢复，断开不可控制旧连接；无不断增长的队列/线程 | 生命周期和连接代次、资源统计 |

| V20 | 原生封面、超大/损坏图片、延迟旧图、跨进程读取 | 可用原生图正确；无越界/内存异常；旧图不覆盖；MB 与 ECARX 均可读取授权 URI | 图像 fixture、Provider 读取结果、实机卡片 |
| V21 | 在线封面/同步歌词、断网/缓存/无匹配/纯文本歌词 | 可匹配测试集展示封面与正确歌词行；暂停/seek 对齐；不匹配明确降级，不串歌 | 两模式卡片、匹配来源/质量、离线结果 |
| V22 | 升级 CarBridge 及 MB，保留设置/信任；并存 DiPlay | 签名有效、设置保留、新协议重握手；不继承错误包名或旧权限假设 | 新旧版本、升级日志、配置对照 |
| V23 | 未受信包调用 IPC、major 不兼容、旧版混搭 | 拒绝未授权控制/资源；清晰降级；不泄漏全量偏好、不启用半套协议 | 身份/协议负面测试 |
| V24 | 目标车方控、音量、Siri 分项探测 | 媒体键真实链可追踪；音量保持正常；语音单独报告可达或未支持，不混同媒体成功 | 原始事件与各项结论 |
| V25 | Geely/BYD/通用 profile 与上游测试 | Geely 无 BYD 专用启动；BYD 测试通过；驻车视频等原有约束保留；同步后重新核验 | profile 测试、上游回归与冲突清单 |
| V26 | 新装/自定义/恢复默认，重连查看 OEM 图标并点击 | 显示 Geely 与黑色纯标，无下方中英文；比例正常；预览一致；返回桌面后连接/音乐保留 | 实际 CarPlay 与设置截图，点击录屏 |

歌曲变化目标：在控制发送后 2 秒内观察可预期的状态/曲目变化；网络缓冲例外记录原因。原生封面在数据完整到达后目标 2 秒内显示；在线资源单独报告耗时与失败率，不把外网超时归为控制链失效。歌词准确性以可验证的同步歌词资源为前提。

## 5. 诊断与证据格式

建议每条关键事件包含 `elapsedMs / processInstance / connectionId / routeEpoch / intentId / commandId / trackGeneration / event / result / reason`。仅有需要的字段才输出；默认不记录原始音频、认证信息、完整设备标识或网络资源凭证。

命令链至少区分：车机回调 → 当前路由接受/拒绝 → HID 提交结果 → iPhone 状态/曲目观测。暂停链至少区分：被新源覆盖 → 本地输出门关闭 → PAUSE 提交 → 手机暂停确认。无法观测手机最终状态时标“未确认”，不写“执行成功”。

每份报告使用以下内容：

```text
测试编号 / 日期 / 执行人
CarBridge 提交与 APK / MediaBridge 提交与 APK / 协议版本
车机 ROM / ECARX / iOS / 播放器 / 连接方式
前置设置与实际路由
步骤与预期
实际结果 PASS / FAIL / NOT RUN
日志时间范围、截图/录屏位置、相关 commandId/epoch
缺陷、复现条件、修复提交、重测结果
```

测试资料保存在明确的本地报告目录或脱敏附件中；涉及私人歌曲列表/设备信息的原始日志不默认提交仓库。可复现的脱敏 fixture 随源码维护。

## 6. 完成与发布门槛

全部必需 V 项有结果，且不存在持续双播、旧状态反抢、重复方控、模式交接双所有者、封面/歌词串歌、Geely 错标或损害原有连接的问题，才能判定完整功能完成。未具备条件的测试写 NOT RUN 并说明交付限制，不把测试计划当结果。

保留一张能力表区分“原生协议已验证”“在线补全已验证”“仅源码/模拟通过”“尚未验证”。G5 发布报告必须列明支持的配套版本和目标车机；后续上游合并按 [同步流程](UPSTREAM_SYNC.md) 执行相关回归。
