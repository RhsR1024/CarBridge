# CarBridge 0.1.3 / MediaBridge 2.3.3 实车候选

日期：2026-10-02。CarBridge versionCode 103；MediaBridge 2.3.3-carbridge-26100204，正式及手机 Debug 均从本地 main 构建。协议仍为 1.0，沿用已有测试签名和用户授权的外部 CarPlay 认证资产。

## 本次修正

- 吉利 / ECARX 配置且“音频焦点”开启时，导航通道检测到非静音 PCM 才申请 USAGE_ASSISTANCE_NAVIGATION_GUIDANCE 对应的临时可压低焦点；保持实际 AudioTrack 属性，包括用户的有效兼容通道。Siri、通话优先于导航。导航静音或停止后释放，不能仅因流未关闭就长期占用。
- 用实际排队音频时长加 600ms 覆盖尾音及短词间隔；静音包不续期。断连立即关闭协调器，禁止旧解码线程重新申请。PCM 仅扫描峰值，不录制或写入诊断。
- CarPlay 前台按当前焦点音轨选择音量控制；默认导航属性在 Android 上若退化为媒体 stream 3，不强制绑定媒体，交给车机基于用途/焦点的音量策略。退到后台恢复 Activity 原有音量设置，焦点随实际导航声音继续工作。OEM 是否支持后台自动选择导航音量仍需实车验证。
- 该逻辑由 CarBridge 音频输出承担，直连与桥接共用；不由 MediaBridge 代申请导航焦点。通用 Android、BYD 配置不启用新导航策略。原音乐互斥、播放意图、车机路由交接和媒体控制继续生效；导航结束不会创建新音乐播放意图。
- 直连音乐信息同时填充“当前歌词句”查询字段及现有更新接口，避免车机通过 getter 查询时为空。仍需真正获得歌词，不能将未匹配歌曲说成已有歌词。

## 新诊断

- 报告头包含本次运行采用的标题格式、原始与处理后的歌名/歌手、未拆分原因、时长；保存的设置另列，避免把重连前运行值当作新设置。
- 音频报告包含实际 usage/content/stream、用户覆盖值、映射和焦点开关、导航活动起止、焦点申请结果/释放及前台音量控制目标。路由设备 type 与 legacy stream 分开，不把 BUS 设备编号当声道。
- CarBridge 直连资源记录资料不足、在线开关、缓存、HTTP 状态或异常类型、匹配拒绝、歌词是否带时间轴和返回长度、过期结果丢弃。资料变为空时也撤销旧查询代次。
- MediaBridge 桥接记录歌词请求编号、可检索条件、启用的来源、来源跳过/匹配和最终结果。沿用现有 CARBRIDGE_METADATA 及导出详细歌曲字段开关。
- 不输出完整歌词、网络响应、音频内容或认证材料。歌曲字段有长度限制；格式诊断按曲目字段变更记录，不按每次进度刷屏。

本轮保持 0.1.2 的严格标题拆分条件，不根据不完整日志新增猜测。实际歌手字段为占位符、分隔符不匹配等情况，需依新日志确定。10:33 的旧日志最后处于 DIRECT/MediaBridge 已让位，不能代表用户较早的桥接播放阶段。

## 实测步骤

1. 覆盖安装 CarBridge 0.1.3 和 MediaBridge 正式包；保留应用数据。车机使用正式版，手机才使用 `-dev` 包。
2. CarBridge 选择吉利 / ECARX，开启音频焦点；媒体通道、导航通道先均为 0；本轮不用猜测厂商数字。标题格式选“歌手 - 歌曲名”，断开后重新连接。
3. 先测 ECARX 直连：播放音乐时滚轮调媒体；触发较长导航播报，在播报中滚动，检查是否调导航、音乐是否仅压低；播报结束约一秒后检查恢复媒体。重复多次，再测后台导航、Siri/通话、导航中暂停或切换到另一音乐 App。
4. 再测自动桥接：MediaBridge 启用桥接、不忽略 CarBridge，确认 CarBridge 实际状态为桥接就绪。重复导航音量、切歌和音乐互斥；检查歌曲/歌手/封面/歌词。桥接歌词使用 MediaBridge 自己的在线检索及来源设置，直连使用 CarBridge 的在线资源开关。
5. 异常发生后尽快导出两份新日志；MediaBridge 勾选详细歌曲字段。记录歌曲、播放器、直连/桥接、前台/后台和大致异常时间，附上音量面板或卡片现象。不要为收集日志重新安装或清除数据。

## 本机验证

最终构建、测试、签名和源码提交证据随交付目录的 manifest.json、SHA256SUMS.txt 与 evidence 保存。车机实际音量映射、桥接/直连的歌曲字段和歌词收录仍由实车验收，本机测试不能替代。
