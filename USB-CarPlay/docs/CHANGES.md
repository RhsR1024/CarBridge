# 修改记录与实现边界

当前 R2 版本见 [控制、设置和歌词更新](CONTROLS_R2_2026-10-03.md)：设置移回原列表，USB 标题格式即时生效，歌词改为三级兜底。下方保留此前版本的分析与历史验证，不作为当前安装入口或时长门槛说明。

## 1. 双指缩放

原 APK 已具备 USB message 23 的多点触控编码，但 `Lcn/manstep/phonemirrorBox/p0/c;->a()Z` 返回 false，CarPlay 只走单点路径。补丁仅把它改为 true，启用已有路径。

原指令 `const/4 v0, 0; return v0` 改为 `const/4 v0, 1; return v0`。不增加新的触控协议，不改盒子固件。用户已反馈修正版可双指缩放。

历史实现和逐字节证据：`history/usb-multitouch/`。

## 2. F25 播放/暂停修正

原 F25 适配把 Android 明确播放 126、明确暂停 127 折叠为切换键 85；而 85 还依赖当前音频焦点。结合重复申请播放源和延迟恢复，可能造成暂停后恢复、暂停状态下播放无反应。

基线包含以下修正：

- 保留 126/127 的明确语义，沿原 `ZqUtil$c → third.c.b → t0.e.H` 链路映射到盒子控制 201/202。
- F25 的播放、暂停、上一曲、下一曲回调派发后正确返回已处理。
- 明确暂停先调用原有焦点释放函数，清除待恢复标记，再发送暂停。
- 注册及纯歌曲信息刷新不申请播放；仅真实非播放→播放转换申请一次车机播放源。
- 原 600 ms 延迟恢复执行前复查焦点与取消标记，避免被取消的恢复继续执行。

相关基线补丁共 10 个方法；多点触控保留。历史源码及 8 类字节码边界回归记录见 `history/usb-f25/`。本次三模式没有继续改动这些控制/焦点函数。

## 3. 纯填充精简

在原始 APK 中发现 `assets/pppppppppppppppppppppppppppppppp.bin`：23,396,044 字节，全部为 `0x50`（字符 P），ZIP 内原样存储。该填充在最初 APK 中已经存在。

精简只移除这一个资源并重新压缩、签名，其余非签名文件内容逐字节相同，包含 DEX、资源、清单和原生库。完整文件名和 basename 的 UTF-8/UTF-16 字面扫描未发现外部引用。静态扫描不能证明任意动态拼接绝不引用该资源，但已确认它是纯重复字节且没有发现使用证据。

用户指定的正式基线：7,545,236 字节；SHA-256：

`10dc853023f48cf0a11f44f99a6da1dd64cb08010550e0b1a72e8030cf94d796`

详见 `docs/evidence/slim-verification.json` 和 `history/usb-size/build_slim.py`。

## 4. 首版自动／直连／MediaBridge 桥接（历史实现）

新增源码位于 `src/cn/manstep/phonemirrorBox/bridge/`：

| 类 | 责任 |
| --- | --- |
| `UsbMediaBridge` | 读取盒子连接标记、接收歌曲增量快照、发布标准媒体会话；明确命令委托原 F25 回调。 |
| `TrackState` | 区分增量歌曲数据与新曲/新连接，避免残留上一首的歌手和专辑。 |
| `F25Direct` | 串行管理车机音乐注册、发布和注销；完整保留原六种媒体回调委托。 |
| `BridgeRoute` | 三模式选择、可信服务绑定、心跳、两阶段交接、旧连接隔离与命令去重。 |
| `BridgeSettings` | 独立偏好文件与设置入口，保留原设置视图及绑定对象。 |

对原 APK 只改四个方法：

1. `com.zqsdk.OooOo00.OooO00o()V`：Android 9+ 接入新的车机侧管理；更旧系统保留完整原初始化。
2. `v0.d.C(String)`：原 JSON 解析和分发完成后，追加只读观察。原参数寄存器会被复用，所以传递仍保留的 JSONObject，不能直接使用方法末尾的 p1。
3. `third.ZqUtil.release()`：原清理之后追加新模块退出。
4. `y.N0(...)`：原设置页创建完成后添加顶部入口，原控件 ID、监听器与数据绑定保留。

后面三处接线删除新增调用后，原指令序列完整一致。原方法总数 37,724，其中 37,720 个方法的指令完全不变。所有原类的字段、继承关系和方法签名保留。

没有改写 `BoxInterface`、USB 收发/编码、音视频、触控、多点开关、原方控路由、`t0.e.H` 或 `e0` 焦点管理。新增代码只读取 `BoxInterface.f.P`，没有对它的写入。没有安装包清单和原生库修改。

## 5. MediaBridge 配套变化

复用协议 1.0：HELLO/POLICY、PREPARE/PREPARED、COMMIT/READY、PLAY/GRANT、PAUSE/YIELD、COMMAND、PING/PONG/CLOSE。通过 UID、精确包名和当前签名认证，并校验进程、连接、epoch、策略版本；命令 ID 去重。

新增 `com.flyme.auto.energy` 身份及其原证书指纹、`usbBox` 能力声明和当前管理包的退出清理。桥接会话只有在协商进入 BRIDGE 后才允许选入；DIRECT、断链、未握手会被排除，原 APK 的空媒体会话仍被过滤。

车机媒体资格与 USB 实际播放分开处理。模式交接、让出通道和失败恢复只改变车机侧发布；不会自动暂停手机、门控 PCM 或制造 USB 恢复播放。明确按键立即进入原控制函数，迟到的资格回执只影响车机侧状态，不再产生迟到的手机播放命令。

MediaBridge 快照来自提交 `03d25c8e9e992d8b15c6d1f276ad4b4504b00603` 加工作区当时已有变更，再添加本次适配；原工作目录未改。历史快照信息与差异位于 `history/mediabridge-base*`。

## 6. 封面、歌词、换曲与断连交接修复

当前版本在固定精简基线上保留首版三模式，并增加原 `v0.d.A(byte[])` 封面回调的只读接线。原方法改动总计五处，其中四处尾部追加调用；USB、音视频、方控、焦点及触控原方法仍逐方法校验不变。详细规则与边界见 [本次修复](METADATA_HANDOFF_2026-10-03.md)。

MediaBridge 两种 CarPlay 的适配已经合入其正式仓库 main，此后修复在该仓库源码完成；本目录中的 2.3.9 快照保留历史用途。当前安装和重建入口以 [USAGE](USAGE.md) 和 [BUILDING](BUILDING.md) 为准。

## 7. 对齐 CarBridge 媒体选项

在“媒体接入 → 媒体选项”增加缺失歌手标题格式和直连在线封面/歌词。前者默认保留原始信息，重新连接生效，仅解析输出副本；后者默认关闭，仅实际直连时生效，使用 CarBridge 同样的 LrcLib/iTunes 服务及完整身份、正时长匹配条件。

`CombinedTitleMetadata`、`SynchronizedLyrics`、`DirectMusicResources` 分别移植标题解析、LRC 时间轴及直连资源逻辑；`DirectSnapshot` 隔离原始状态，`DirectArtworkCache` 复用 APK 已有 FileProvider 提供有界图片缓存和读权限。原生封面、歌词和可信进度也接入 F25 SDK，原生内容优先。

新增资源刷新仅发布元数据；切模式/断连取消在线任务，旧曲结果不得覆盖新曲，不回写盒子原始字段，不合成 USB 命令，不申请恢复播放。与上一修复版相同，原方法仍只有五处接线。详见 [实现与验证](MEDIA_OPTIONS_2026-10-03.md)。
