# 收藏忽略名单试验（26092808）

## 需求与依据

用户要求原车小窗对所有桥接播放器默认显示收藏红心，设置页维护独立的“收藏忽略名单”：勾选某应用只隐藏其红心，不停止桥接。临时“探测改包网易云”按钮应从页面移除。

实车日志 `mediabridge-probe-20260928-133242-821.log.txt` 证明改包网易云 `.iou` 虽然 `PlaybackState.actions=0`，但心形 `setRating()` 有四次获得播放器状态确认；其中一次 13:32:17 发出后未在 3 秒内确认，旧逻辑撤销车机收藏能力，红心消失，下一首歌才恢复。因此不能把“动作位为零”当作所有播放器一定不可收藏，也不能把一次超时当作收藏成功。

## 26092808 行为

- 保留全局“显示收藏”总开关，默认开启；新增独立 `favorite_ignore_packages` 集合，默认空。候选应用来自历史已发现、当前活动和已加入收藏忽略的包名；勾选表示隐藏该应用红心。支持手动添加和清空。原“应用忽略名单”保持原意，不与收藏名单混用。
- 总开关开启且当前应用未被收藏忽略时，车机上报 `supportCollect=true`；不再因为收藏状态未知或请求正在确认就撤销红心。车机服务若拒绝能力声明，仍不能强制让它显示。
- 点击才尝试实际收藏：优先已有通知操作、自定义动作和播放器明确支持的评分；无声明但评分类型为 HEART/THUMB/NONE 时，试发对应评分，NONE 时试用 HEART。其他评分类型不冒充心形收藏。请求发出不等于成功，仍等待播放器状态回传。
- 无可调用路径、发送异常时提示“收藏失败”；3 秒没有回传、切歌或播放器断开时提示“收藏失败或未确认”，保留红心以供重试。MediaBridge 设置页、诊断日志和系统 Toast 均提供失败信息；Toast 能否覆盖车机小窗需实车确认。状态未知时小窗可能显示空心红心，不能据此外推播放器实际收藏状态。
- 页面移除“探测改包网易云”按钮及说明，保留通用“导出诊断日志”。底层旧只读探针代码暂留，不影响普通操作。

## 建议实车验证

1. 保持“显示收藏”开启、收藏忽略名单为空，依次播放酷我、汽水、酷狗、LX 和改包网易云，确认小窗红心是否出现，原有方控、播放按钮、封面和歌词是否保持正常。车机如果拒绝能力声明，导出的日志会有 `FAVORITE_PROBE side=vehicle event=declareCollect`。
2. 每个播放器选一首未收藏歌曲点红心，回到播放器核对真实收藏结果；再尝试取消。特别记录红心点按后的提示、是否保持显示，以及歌切换后的状态。
3. 对确实不支持或不希望展示收藏的应用，在“收藏忽略名单”勾选；确认仅红心消失，其他桥接功能仍可用。取消勾选后红心应恢复。
4. 若有失败或红心未出现，导出诊断日志，并说明播放器、歌曲和操作时间；不要仅凭小窗按钮动画判断成功。
