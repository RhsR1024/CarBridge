## 1. 审查结论

**当前项目没有完全完成 SPEC 和 PLAN，也没有达到“保留原版全部相关媒体功能，并修复问题、增加新功能”的交付条件。**

它已具备可以构建的标准通道主体、会话发现、基本方控、歌词、封面缓存和重试框架；但存在真实代码缺陷、原版能力遗漏和尚未实现的工作，不只是缺少实车记录。特别是 F25 仍为直接返回不兼容的占位后端，不能称为双模式实现。

本次归并出 **17 组主要问题：7 组 P1、10 组 P2**。P1 表示核心功能缺失、核心恢复失效或会造成错误控制/状态，应优先处理；P2 表示明确功能缺口、兼容性回归或可诊断性问题。每组可能包含同一模块的多个相关触发场景，不能把组数当成全部缺陷数量。

本地现有 10 项 JVM 测试、Lint、debug/release 构建全部通过。独立审查探针仍复现了模式状态、超时回调、回退微调、收藏方向和 LRC 解析问题，说明现有测试不足以证明规格已完成。

建议将当前版本定位为：**标准通道开发测试版，存在待修复问题；F25 未实现；目标车验收未完成。** 不建议把它作为已经完整替代原版的稳定交付版本。

协调器定时器使用主线程 Handler；MediaCenterAPI 将 ready 回调切到主线程，然后同步注册。EAS init/getMainBinder、注册、焦点查询、快照/歌词/进度发送及注销均直接执行同步 IPC。每秒播放器进度刷新还会再次进入封面 URI 解码/缓存路径。

### F03 · P1 · IPC 失败和 token 失效没有闭合到恢复状态机，拒绝也被当成普通重试

证据：[mediacenter/MediaCenterAPI.java:393](D:/车机软件/MediaBridgeApp/MediaBridge-src/app/src/main/java/com/ecarx/eas/sdk/mediacenter/MediaCenterAPI.java:393)、[mediacenter/MediaCenterAPI.java:402](D:/车机软件/MediaBridgeApp/MediaBridge-src/app/src/main/java/com/ecarx/eas/sdk/mediacenter/MediaCenterAPI.java:402)、[LegacyBackend.java:166](D:/车机软件/MediaBridgeApp/MediaBridge-src/app/src/main/java/com/geely/auto/music/LegacyBackend.java:166)、[LegacyBackend.java:68](D:/车机软件/MediaBridgeApp/MediaBridge-src/app/src/main/java/com/geely/auto/music/LegacyBackend.java:68)。原版主动检查及重注册见 [UniversalBridgeService.java:120](D:/车机软件/MediaBridgeApp/sources/com/geely/auto/music/UniversalBridgeService.java:120)。

多个 API 捕获异常后直接返回 false/null 或吞掉异常。publishSnapshot 发现 updateMusicPlaybackState=false 时只写日志，不作废 token、不通知协调器、不重新注册。进度/歌词/来源更新失败也不传播到协调器。

**触发一：** 服务 Binder 仍然存活，但注册 token 已被服务端清理或拒绝。系统不会必然产生 Binder death；应用可以长期保持“已注册”，不断发送失败，只有人工重连才恢复。

**触发二：** bind/register 抛 SecurityException 或协议拒绝。Legacy 路径把它们折叠为“服务暂不可用/注册失败”，不会产生 ACCESS_DENIED/INCOMPATIBLE，仍按普通故障无限重试。F25 占位会报不兼容，不等于标准后端具备错误分类。

**应修复：** 传递结构化错误；识别连接/注册失效并完整重连；明确拒绝停止无意义重试；把“歌词不支持”等局部能力失败与连接失败分开。对应 SPEC §9.1–9.2，PLAN P3.1/P3.3/P4。

### F04 · P1 · 超时/失败后没有立即作废旧代次和控制入口

证据：[BridgeCoordinator.java:115](D:/车机软件/MediaBridgeApp/MediaBridge-src/app/src/main/java/com/geely/auto/music/BridgeCoordinator.java:115)、[BridgeCoordinator.java:130](D:/车机软件/MediaBridgeApp/MediaBridge-src/app/src/main/java/com/geely/auto/music/BridgeCoordinator.java:130)、[BridgeCoordinator.java:175](D:/车机软件/MediaBridgeApp/MediaBridge-src/app/src/main/java/com/geely/auto/music/BridgeCoordinator.java:175)、[LegacyMusicClient.java:210](D:/车机软件/MediaBridgeApp/MediaBridge-src/app/src/main/java/com/geely/auto/music/LegacyMusicClient.java:210)。独立探针见附录 A。

超时只进入 scheduleRetry；此时未 close 旧后端，也未递增 generation。generation 要到下一次 connectAttempt 才改变。LegacyMusicClient.request 只检查 snapshot 和 generation，没有检查协调器是否仍处于 REGISTERED。

**复现：** 启动连接 → 15 秒超时 → 等待 2 秒重试期间注入同一代次 REGISTERED。该回调被接受，待执行重试被取消。探针输出 backendClosed=false、generationUnchanged=true、late accepted=true。

**影响：** 超时后的旧任务可以复活连接状态；失败到重试之间旧客户端仍可能提交控制请求，不满足“整条旧连接作废”的要求。应在失败/超时确定时先禁用控制并使尝试失效，再进行清理和调度。对应 SPEC §6.3/§9.2，PLAN P4/P7.3。

### F06 · P1 · 收藏动作方向和当前歌曲归属缺少可靠判断

证据：[FavoriteActionPolicy.java:15](D:/车机软件/MediaBridgeApp/MediaBridge-src/app/src/main/java/com/geely/auto/music/FavoriteActionPolicy.java:15)、[MediaListenerService.java:563](D:/车机软件/MediaBridgeApp/MediaBridge-src/app/src/main/java/com/geely/auto/music/MediaListenerService.java:563)、[MediaListenerService.java:683](D:/车机软件/MediaBridgeApp/MediaBridge-src/app/src/main/java/com/geely/auto/music/MediaListenerService.java:683)、[MediaListenerService.java:703](D:/车机软件/MediaBridgeApp/MediaBridge-src/app/src/main/java/com/geely/auto/music/MediaListenerService.java:703)。独立探针见附录 A。

通用策略把名称包含 LIKE/FAV/HEART/LOVE、又没有 ADD/REMOVE 等片段的动作当作 toggle，不校验其真实语义和当前状态。只有一个单向 LIKE 的播放器，收到“取消收藏”仍会被发送 LIKE。探针已复现 select([LIKE], false) 返回 LIKE。

对于真实 toggle 接口也没有判断“当前已是目标状态就不执行”。重复的“设为收藏”可能切回未收藏；状态未知时更无法可靠完成 setFavorite(true/false)。

另外，pendingFavorite 仅绑定包名和 session，未绑定曲目。**同一播放器、同一 session 在 3 秒内切歌**时，上一首的待确认目标可能被 publish 套到新歌上，直到超时或收到其他反馈。控制 Intent 同样没有 track id，收藏不是只校验 session 就足够。

**应修复：** 将 SET_TRUE/SET_FALSE/TOGGLE 分开，只有已核实适配器可以解释动作；为收藏请求和确认携带曲目标识/曲目代次，切歌立即清理待确认状态。对应 SPEC §6.2/§7.2，PLAN P6.2/P6.3。

## 8. 已确认的正确方向与没有采用的误报

- 包名和通知监听兼容全限定名保留；应用未声明 sharedUserId。
- 发布 APK 权限仅 INTERNET、ACCESS_NETWORK_STATE、FOREGROUND_SERVICE、FOREGROUND_SERVICE_SPECIAL_USE、POST_NOTIFICATIONS、RECEIVE_BOOT_COMPLETED；未包含原息屏/AVAS/系统自授权权限。
- 标准 EAS 主 Binder、direct fallback、注册客户端、source 6、主要回调接口已经落地，不是仅有界面。
- 显式 PLAY/PAUSE 分支分开，没有照搬把两者都变 TOGGLE 的做法。
- 控制目标含包名/session/连接代次，按键没有被历史队列重放；只是还存在F04/F06所列边界。
- 自动选择保留暂停目标，最近进入PLAYING有时间记录，忽略和固定有独立行为；没有把近似包名合并。
- 内部Service命令使用随机nonce，Provider不导出、只读、限制文件名，方向正确。ECARX发现入口导出是协议兼容需求，不能单凭exported=true就断言任意第三方能发送收藏命令。
- 原版“默认所有播放器支持收藏”不是本次可保留的正确行为，因为SPEC明确要求修复；反过来，Spotify通用rating可覆盖的能力也不能因为未保留同名类就算全部丢失。
- 原版已有的空播放列表/空推荐接口，没有被夸大为完整歌单功能。本期不因Cplay中存在盒子/投屏类而要求复制商业业务。
- 缺少实车证据不等于代码必定失败；本报告标明哪些是已经证明的代码差异，哪些需要目标端确认。
