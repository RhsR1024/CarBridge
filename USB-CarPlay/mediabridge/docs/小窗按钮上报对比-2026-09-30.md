# MediaBridge 与 LX / Wayfarer 的车机小窗按钮对比

日期：2026-09-30。比较对象为当前 MediaBridge 分支与 `D:/WorkSpace/lx-music-new/lx-music-new-src` 中的 Wayfarer；后者安装包名为 `com.wayfarer.music`，不是旧版 `cn.toside.music.mobile`。

用户实测旧 MediaBridge 小窗有六个按钮，Wayfarer 有三个。此次只调查差异，不新增、删除或模拟按钮。新独立包名 APK 尚未在目标车安装，不能将旧包六按钮的结果直接套到新包。

## 已确认的上报差异

| 项目 | MediaBridge | Wayfarer | 可以得出的结论 |
| --- | --- | --- | --- |
| 上一曲、播放/暂停、下一曲 | 实现车机 MusicClient 控制回调并转发给当前播放器 | 自定义 MusicClient 实现相应回调 | 两者都提供基本播放控制 |
| 收藏能力 | 按收藏开关及“收藏忽略名单”调用 `declareSupportCollectTypes`，并设置 `isSupportCollect` | 自定义播放信息没有覆盖 `isSupportCollect`；SDK 默认返回 false | 收藏有明确的能力上报差异，解释了 Wayfarer 未提供收藏入口；最终是否画按钮仍由车机决定 |
| 当前播放列表 ID | 固定提供实际包名加 `-play-list-common` | 自定义播放信息没有覆盖该方法；SDK 默认返回 null | 列表关联信息有差异，但不能单凭此字段认定它就是按钮开关 |
| 列表查询 | `getContentList/getPlaylist` 返回空列表，`getMultiMediaList` 返回 null | 自定义 MusicClient 没有覆盖这些查询，SDK 默认返回 null | 两者都不能凭按钮存在就声称已实现完整列表功能；空列表和 null 是否影响显示需验证 |
| 推荐内容 | `onPlayRecommend/onCancelRecommend` 返回 false，扩展回调无推荐实现 | 未发现自定义客户端实现推荐控制 | 不能把旧 MediaBridge 推荐按钮出现解释为已上报可用推荐歌单 |

MediaBridge 关键位置：

- [LegacyBackend.java](../app/src/main/java/com/geely/auto/music/LegacyBackend.java)：`registerClient`、`publish`、`requestPlayFocus` 中的收藏能力声明。
- [LegacyMusicClient.java](../app/src/main/java/com/geely/auto/music/LegacyMusicClient.java)：`clear/refreshInfo` 中的 `setPlayingMediaListId` 和 `setSupportCollect`；收藏及基础控制回调。
- [MusicClient.java](../app/src/main/java/com/ecarx/eas/sdk/mediacenter/MusicClient.java)：列表查询默认实现及能力常量。
- [MusicClientWrapper.java](../app/src/main/java/com/ecarx/eas/sdk/mediacenter/MusicClientWrapper.java)：列表查询转发、推荐回调及现有 `ECARX_PROBE` 日志。

Wayfarer 关键位置（均相对于上述参考工程）：

- `tools/vehicle-extension/smali/com/wayfarer/music/ecarx/WayfarerMusicClient.smali`：车机自定义客户端实际覆盖的方法；上一曲、下一曲、播放/暂停分别可见于 `onPrevious/onNext/onPlay/onPause`。
- `tools/vehicle-extension/smali/com/wayfarer/music/ecarx/WayfarerMusicPlaybackInfo.smali`：自定义播放信息未覆盖 `isSupportCollect/getPlayingMediaListId/getPlayingMediaListType`。
- `app/src/main/java/com/ecarx/eas/sdk/mediacenter/MusicPlaybackInfo.java:100`：列表 ID 默认 null；`:105` 列表类型默认 0；`:160` 收藏能力默认 false。
- `app/src/main/java/com/ecarx/eas/sdk/mediacenter/MusicClient.java:33`、`:53`、`:63`：内容、多列表、播放列表默认返回 null。
- `app/src/main/java/p002a2/C0218l.java` 的反射处理器虽然存在 `getPlaylist` 分支，但自定义 MusicClient 没有对应覆盖方法，不能仅凭这段分支判断它实际向车机提供了列表。
- `app/src/main/java/B0/RunnableC0016c.java:323` 有主动 `updatePlaylist` 调用；这与“车机画出列表按钮”仍是两件事。

## 不能混淆的注册参数

MediaBridge 的 `capabilities = [0, 2, 3]` 在 SDK 中分别表示方控、仪表、Widget 三种交互通道，不是三个额外按钮，也不是六按钮布局声明。

`declareSupportCollectTypes([0, 3, 4])` 表示音乐、电台、新闻的收藏类型，同样不是按钮数量。

`res_mediacenter.xml` 的 `semantic-list` 是媒体语义能力配置，现有 SDK 中 `67108865/33554434/33556480` 对应播放音乐、暂停、关闭；没有证据表明这组数值直接规定小窗六按钮布局。

来源目录 `AppSourceConfig` 解决“下拉列表中有没有这个应用”。收藏能力、播放列表信息及车机 UI 规则解决“选中它后显示哪些内容”。来源登记成功不保证按钮布局与旧包一致。

## 尚未证实的车机规则

旧 MediaBridge 使用 `com.netease.cloudmusic.iot`，并带有 `isGeelyCloudMusic` 等网易云身份信息。车机可能据此选择官方网易云的专用布局，从而显示推荐与播放列表入口。但目前没有目标车小窗 UI 的布局选择源码或运行证据，故只列为假设，不能写成确定原因。

本轮独立包改为 `com.mediabridge.app`，移除这些身份信息，保留原有收藏、列表 ID 和控制上报。新包按钮数可能变化，需要实车记录。六按钮出现不等于六项功能均可用。

验收时先记录新包按钮布局，再分别切换收藏开关及“收藏忽略名单”观察红心；点击列表、推荐后导出日志，查看是否出现 `ECARX_PROBE getPlaylist/getMultiMediaList/onPlayMediaList/onPlayRecommend`。没有回调只能说明这次操作没有走已记录的接口，不能据此推导所有车机规则。

不要为减少按钮直接清空列表 ID：历史探针曾出现 `queueId == null` 播放状态错误，见 [播放列表探针分析](播放列表探针分析-2026-09-28.md)。后续如需调整列表声明，应单独验证播放状态和方控回归。
