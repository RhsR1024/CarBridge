# 改包网易云 `.iou` 只读探针

## 范围与基线

- 分支：`probe/iou-native-source-260928`，从已实车验证的 `v26092802-verified-four-player-baseline`（`c455eea`）创建。主分支和四播放器控制/封面/歌词路径未修改。
- 目标是判断仅修改 MediaBridge 能否接入已重签、改包名的车机网易云 `com.netease.cloudmusic.iou`；本 APK **尚未宣称能桥接它**。
- 用户提供的实际安装包与原车包的 DEX 相同，前者主要改了 Manifest 包名并重新签名；静态检查未发现标准 `MediaSession`/`MediaBrowserService` 对外声明。旧诊断日志没有 `.iou` 媒体会话，仍需要实车主动探测。

## 探测内容

在设置页的“导出诊断日志”卡片新增“探测改包网易云”。点击后：

1. Android 通知监听侧记录 `.iou` 包是否可见、全部活动 MediaSession 的包名、`.iou` 会话的播放状态/动作/元数据/队列长度，以及 `.iou` 通知是否携带 `EXTRA_MEDIA_SESSION` token。仅记录字段是否存在，不记录歌曲文本。
2. 已注册的车机 MediaCenter 侧，在独立后台线程查询当前焦点客户端，以及三个只读 Binder 入口是否存在及其接口描述。异常仅写日志，不进入桥接失败回调，也不触发重连、控制、注册或发布。
3. 探针动作使用现有内部 nonce 校验。未授权通知监听或桥接未注册时，日志会明确说明，不能把这种空结果误判为 `.iou` 一定没有接口。

探针没有自动识别 `.iou` 私有播放协议，也没有获取车机网易云当前曲目或调用其播放控制；它不能代替实车协议验证。若 `.iou` 没有 MediaSession 且车机只提供该应用私有 IPC，可能需要专用适配器；若私有 IPC 强制原厂签名或 shared UID，仅改本项目也可能无法接管。

## 实车步骤

1. 使用本探针包覆盖安装相同测试证书签名的 MediaBridge；不要卸载 `.iou` 播放器。若系统提示签名不一致，停止覆盖并保留现有安装/数据。
2. 启用桥接和通知访问；让 `.iou` 播放一首歌，保持播放页面，打开 MediaBridge，点“探测改包网易云”。
3. 等待至少 5 秒，点“导出”，发送 `Download/MediaBridge` 下最新诊断日志。最好再做一次酷狗或酷我正常播放的对照探测。
4. 日志中检索 `IOU_PROBE`，重点查看 `targetSession`、`targetNotification`、`focusClient`、`controllerApi`、`controlClientApi`、`stateBinder`。若 `event=end` 缺失，说明只读 Binder 调用可能卡住，需要如实报告，不应推断接口不可用。
5. 实车验证完可重新安装基线 APK；基线代码标签和 APK 哈希见 `TEST_LOG.md`。探针的正常四播放器功能仅完成自动化回归，尚未在目标车复测。
